# 09 · MVP 交付范围与可验证验收

## 事实边界

本次是现有 FastAPI/SQLite/vanilla JS 平台的增量 MVP，不是组织平台全量建成。先完成不依赖模型的项目加入闭环，再验证适配器，最后由负责人决定是否生产部署。代码存在、自动测试通过、本地人工验证、真实 Agent 验证和生产验收是五种不同证据，不可互相替代。

代码事实初审见 [00](00-current-system-review.md)，固定契约见 [04](04-api-and-workflows.md)，运行和人工发布检查见 [运行手册](../../AGENT_INTERFACE_MVP.md)。旧设计中的设备借用、OAuth/OIDC、Gitea、官网模型、远程 MCP 和两种真实 Agent 兼容均不是本次既成事实。

## 本次范围

1. 复用当前账号的 `member/admin` 组织身份，逐请求重新鉴权，隔离旧网页 Bearer 与短时 CLI grant；applicant 拒绝组织权限。
2. CLI 一次性授权码签发/交换、本人 grant 分页与撤销；不实现 OAuth/OIDC。
3. `/me`、能力发现、分页项目目录与知识检索/文档读取、项目加入 schema。
4. 持久草稿、无副作用 validate、仅可信网页取得确认 token、`draft_id + confirmation` 幂等提交、本人列表/详情、网页 admin review。
5. CLI 与本地 stdio MCP 作为相同 API 的适配层；服务器授权不依赖 Skill、模型或工具描述。
6. 本地运行、受控知识同步、SQLite 一致备份/恢复与回滚说明；实际生产操作由人工另行执行。

## 本地无模型端到端验收

在隔离的空测试数据库中准备 member、admin、applicant 和两个成员可见性不同的资源：

1. 网页 member 登录，CLI 用最小 scopes 完成授权；网页和 CLI 查询得到同一允许项目。
2. CLI/本地 MCP 检索来源明确的文档，准备与校验项目加入草稿，确认响应不包含确认 token。
3. 人工在可信网页审阅并确认，提交后得到稳定申请 ID；模拟网络重试不产生第二条申请。
4. 本人查状态、另一成员访问被拒、网页 admin 审核；CLI 和已降级 admin 的 review 被拒。
5. 撤销 grant、变更角色后重复读取/提交，被服务端拒绝。
6. 不启动任何 LLM/Gitea/远程 MCP，业务仍可完成。

HTTP 自动测试能证明对应服务端行为；不能仅凭它宣称浏览器点击、跨平台安装、真实 MCP Host 或人类确已看过内容已验证。

## 另行人工验收与上线门禁

- 两种真实 Agent：一种 MCP Host、一种命令行 Agent，记录具体客户端/版本、系统、工具输出与负面权限案例；未执行写“未验证”。本地协议测试不算两个真实客户端。
- 硬件：在目标机器记录 CPU/RSS/响应时间/磁盘增长、轻负载与同步时表现，之后才能给吞吐与容量结论。
- 运维：确认 authoritative/edge 的新路由和写入权威，失联时不得在 edge 建第二个事务权威库；完成离机备份与隔离恢复演练，记录 RPO/RTO 和责任人。
- 生产：人工审核 TLS、反代路径、凭据存储、权限、审计保留、数据分级、目录来源、旧端兼容和回滚点；使用脱敏测试账号做发布后 smoke test。
- 部署与恢复均未因本次文档更新而执行。没有上述证据，交付应表述为“本地 MVP/待部署”，而非“已上线/安全验收完成”。

## 后续阶段（非本次承诺）

按正式制度逐步扩展真实事务、指派审核与项目 ACL；补件/撤回 API 已实现并有自动测试，但对应真实浏览器操作仍需人工验收，不能仅凭状态枚举或接口测试宣称完整用户体验已验证。需要时再设计标准 OAuth 委托、Gitea 逐仓镜像、远程 MCP 与可选官网模型。每项单独评审、测试、回滚并获人工发布授权，不把未来端点放入本次已实现清单。
